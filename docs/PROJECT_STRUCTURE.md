# Project structure

Four rules keep this layout clean:

1. **The app only uses `frontend/` and `assets/`.** Nothing under
   `experiments/` or `datasets/` is ever loaded by a browser.
2. **Scripts never build paths from their own location.** Every path comes
   from [`backend/paths.py`](../backend/paths.py), so moving a folder means
   changing one line.
3. **Raw data is read-only.** `datasets/raw/` and the linked `datasets/videos/`
   and `datasets/landmarks/` are only ever read. Everything derived goes to
   `datasets/processed/` (build-side) or `assets/` (what the app loads).
4. **Experiments are archived, not maintained.** They keep the code and
   outputs exactly as they were, for reference.

## The linked datasets

`datasets/videos/rgb` and the files under `datasets/landmarks/` are
relative symlinks to the original workspace, so 5.5 GB is not duplicated.
They resolve as long as `auslan-ai-clean/` stays inside the original folder.
If you move the project, re-point them, for example:

```sh
ln -sfn "/new/place/rgb" datasets/videos/rgb
```

Nothing else needs changing: every script finds the data through
`backend/paths.py`.

## Experiments run from where they were

The archived experiments are byte-for-byte what they were, including their
paths, which are relative to the original workspace root (e.g. `"19.mp4"`,
`"rgb/40255_kf_rgb.mp4"`). To re-run one, run it from the original
workspace, where its inputs still sit beside it. They are kept for
reference and history; none of them is part of the production pipeline.
